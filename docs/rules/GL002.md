# GL002: errexit disabled before a scanner

| Severity | Platforms |
| --- | --- |
| HIGH | GitHub Actions, GitLab CI |

## Risk

"set +e" (or a custom shell started without -e, such as "shell: bash {0}") turns off errexit, so the script keeps going after a command fails. When a scanner runs while errexit is off and it is not the last command of the script, its failure is lost: the step's exit status is that of whatever runs last. gatelint does not report the pattern when the next command reads $? (for example "rc=$?") or when the scanner is the final command, because then the status still reaches the runner.

## Fix

Remove "set +e", or capture the status with rc=$? and exit with it.

Before:

```yaml
- name: Scan
  run: |
    set +e
    gitleaks detect --source .
    echo "scan finished"
```

After:

```yaml
- name: Scan
  run: |
    gitleaks detect --source .
    echo "scan finished"
```

## Suppressing

If the finding is a deliberate exception, suppress it on the same line or the line directly above, with a reason of at least 10 characters:

```yaml

```
