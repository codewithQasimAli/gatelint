# GL004: continue-on-error on a scanner step or job

| Severity | Platforms |
| --- | --- |
| HIGH | GitHub Actions |

## Risk

"continue-on-error: true" tells GitHub Actions to treat a failed step (or job) as a success. On a scanner step this keeps the workflow green whatever the scanner finds; the only trace is a warning annotation that is easy to miss. When the value is an expression such as "${{ matrix.experimental }}", gatelint reports it at medium severity as conditional, because the gate is only disabled for some runs.

## Fix

Remove continue-on-error, or move non-blocking experiments to a separate job.

Before:

```yaml
- name: Semgrep
  run: semgrep ci
  continue-on-error: true
```

After:

```yaml
- name: Semgrep
  run: semgrep ci
```

## Suppressing

If the finding is a deliberate exception, suppress it on the same line or the line directly above, with a reason of at least 10 characters:

```yaml
# gatelint:ignore GL004 <why this is acceptable and where the real gate is>
```

See the [rule index](../../README.md#rules) for the other rules. `gatelint rules GL004` prints this description in the terminal.
