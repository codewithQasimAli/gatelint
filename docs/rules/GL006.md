# GL006: Neutering flag on the scanner command line

| Severity | Platforms |
| --- | --- |
| HIGH | GitHub Actions, GitLab CI |

## Risk

Many scanners have a flag that keeps the exit code at 0 whatever they find: Bandit's --exit-zero, Checkov's and tfsec's --soft-fail, gosec's -no-fail, "--exit-code 0" for Trivy and Gitleaks, "npm audit --audit-level=none". The same applies to the equivalent environment variables, such as TRIVY_EXIT_CODE=0. The flag is often added "temporarily" to get a pipeline green and never removed. gatelint knows each scanner's flags from its catalog, which can be extended in .gatelint.yml.

## Fix

Remove the flag so the scanner exits non-zero on findings.

Before:

```yaml
script:
  - bandit -r src --exit-zero
```

After:

```yaml
script:
  - bandit -r src
```

## Suppressing

If the finding is a deliberate exception, suppress it on the same line or the line directly above, with a reason of at least 10 characters:

```yaml
# gatelint:ignore GL006 <why this is acceptable and where the real gate is>
```

See the [rule index](../../README.md#rules) for the other rules. `gatelint rules GL006` prints this description in the terminal.
