# GL001: Scanner failure swallowed by the shell

| Severity | Platforms |
| --- | --- |
| HIGH | GitHub Actions, GitLab CI |

## Risk

The scanner's exit status is discarded by the shell, so a failing scan can never fail the job. The usual culprit is "|| true", but "|| :", "|| exit 0", "|| echo ...", a leading "!", running the scanner inside $(...) as an argument of another command, running it in the background with "&", using it as an if condition without a failing branch, and putting it on the left of "&&" in the middle of a script (bash exempts that command from errexit) all have the same effect. The scanner still runs and prints findings, so the job looks protected while it is not. gatelint only reports this when the swallowed command is a known scanner.

## Fix

Remove the "|| true" (or equivalent) so a failing scan fails the job.

Before:

```yaml
- name: Scan image
  run: trivy image --exit-code 1 myapp:latest || true
```

After:

```yaml
- name: Scan image
  run: trivy image --exit-code 1 myapp:latest
```

## Suppressing

If the finding is a deliberate exception, suppress it on the same line or the line directly above, with a reason of at least 10 characters:

```yaml
# gatelint:ignore GL001 <why this is acceptable and where the real gate is>
```

See the [rule index](../../README.md#rules) for the other rules. `gatelint rules GL001` prints this description in the terminal.
