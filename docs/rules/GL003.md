# GL003: Scanner piped without pipefail

| Severity | Platforms |
| --- | --- |
| MEDIUM | GitHub Actions, GitLab CI |

## Risk

Without pipefail, a pipeline's exit status is that of its last command. "trivy image app | tee report.txt" therefore succeeds whenever tee succeeds, whatever Trivy found. On GitHub Actions the default shell for Linux and macOS runners when "shell:" is omitted is "bash -e {0}", which does not set pipefail; "shell: bash" runs "bash --noprofile --norc -eo pipefail {0}" and does. "shell: sh" runs "sh -e {0}" without pipefail. GitLab Runner enables pipefail where the shell supports it, so on GitLab this rule only fires after an explicit "set +o pipefail".

## Fix

Set "shell: bash" on the step (it adds -o pipefail) or add "set -o pipefail" before the pipeline.

Before:

```yaml
- name: Scan
  run: trivy fs --exit-code 1 . | tee trivy.txt
```

After:

```yaml
- name: Scan
  shell: bash
  run: trivy fs --exit-code 1 . | tee trivy.txt
```
