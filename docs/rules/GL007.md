# GL007: Scanner does not gate by default

| Severity | Platforms |
| --- | --- |
| MEDIUM | GitHub Actions, GitLab CI |

## Risk

Some scanners report findings but exit 0 unless asked to fail: Trivy needs --exit-code 1, Grype needs --fail-on, "semgrep scan" needs --error, TruffleHog needs --fail, and aquasecurity/trivy-action needs exit-code set to a non-zero value. Without the gating option the scan is informational only, which is easy to miss because the job log is full of findings. "snyk monitor" never fails on vulnerabilities and is reported at info severity; use "snyk test" to gate. When the gating option comes from a configuration file or an expression gatelint cannot evaluate, the scanner is listed as "unknown" in the coverage summary instead.

## Fix

Add the scanner's gating option so findings fail the build.

Before:

```yaml
- name: Trivy
  uses: aquasecurity/trivy-action@0.28.0
  with:
    scan-type: fs
```

After:

```yaml
- name: Trivy
  uses: aquasecurity/trivy-action@0.28.0
  with:
    scan-type: fs
    exit-code: '1'
```

## Suppressing

If the finding is a deliberate exception, suppress it on the same line or the line directly above, with a reason of at least 10 characters:

```yaml
# gatelint:ignore GL007 <why this is acceptable and where the real gate is>
```

See the [rule index](../../README.md#rules) for the other rules. `gatelint rules GL007` prints this description in the terminal.
