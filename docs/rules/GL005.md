# GL005: Scanner job allowed to fail

| Severity | Platforms |
| --- | --- |
| HIGH | GitLab CI |

## Risk

"allow_failure: true" lets a GitLab job fail without failing the pipeline; the merge request shows a warning icon and can still be merged. "allow_failure: exit_codes" does the same for specific exit codes, and when those include the scanner's failure code (1 for most tools, 2 for Grype with --fail-on, 183 for TruffleHog, or the value given to --exit-code) the scan can never block the pipeline. The same applies to an allow_failure inside rules: when it covers every rule that runs the job (reported as conditional when only some rules set it), and to scanners placed in after_script, whose exit status GitLab ignores.

## Fix

Remove allow_failure from the scanner job (or drop the scanner's failure code from exit_codes).

Before:

```yaml
trivy:
  stage: test
  script:
    - trivy fs --exit-code 1 .
  allow_failure: true
```

After:

```yaml
trivy:
  stage: test
  script:
    - trivy fs --exit-code 1 .
```
