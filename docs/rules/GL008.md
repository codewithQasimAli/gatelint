# GL008: Neutering input on a scanner action

| Severity | Platforms |
| --- | --- |
| HIGH | GitHub Actions |

## Risk

Scanner actions expose inputs that keep the step green whatever is found: aquasecurity/trivy-action with exit-code: '0', anchore/scan-action with fail-build: false, bridgecrewio/checkov-action and aquasecurity/tfsec-action with soft_fail: true, pypa/gh-action-pip-audit with internal-be-careful-allow-failure: true, and neutering flags passed through an args input (for example securego/gosec with args: -no-fail). These inputs are usually added to unblock a release and then forgotten.

## Fix

Remove the input (or set it to its gating value) so findings fail the step.

Before:

```yaml
- uses: anchore/scan-action@v6
  with:
    image: myapp:latest
    fail-build: false
```

After:

```yaml
- uses: anchore/scan-action@v6
  with:
    image: myapp:latest
    severity-cutoff: high
```

## Suppressing

If the finding is a deliberate exception, suppress it on the same line or the line directly above, with a reason of at least 10 characters:

```yaml
# gatelint:ignore GL008 <why this is acceptable and where the real gate is>
```
